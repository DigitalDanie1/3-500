# 3대 500

https://3-500.vercel.app/

루트의 `index.html` 및 CSS/JavaScript 파일을 그대로 제공하는 정적 사이트입니다. 빌드 단계나 서버는 필요하지 않습니다.

## 지금 기준 (2026-10)

- 실측 1RM: 스쿼트 140 · 벤치 105 · 데드리프트 135 = 380. 새 플랜은 2026-10-19(월) 1주차
- 첫 방문 시 「새 플랜으로 시작」 안내 — 누르면 1RM 칸을 실측값으로 맞추고 시작일을 10/19로 잡음
- 데드가 스쿼트보다 낮아(덜 훈련됨) 금요일 데드는 멈춤 데드리프트 5×3 @ 1RM 65%

## 식단 탭

- '번' 칼로리 앱(calories-sand-five.vercel.app)과 같은 음식 102개 목록, 아침·점심·간식·저녁 기록, 0.5~2인분 및 직접 배수, 직접 추가 음식 저장
- 체중 관리: 78~79kg 유지 (식단 → 내 정보에서 변경). 7일 평균이 79kg 위면 감량, 78kg 밑이면 증량, 사이면 유지
  - 감량(목표+0.5kg 초과 또는 상한−0.3kg 도달): 유지 칼로리 −200(훈련일) / −450(휴식일), 단백질 2.2g/kg
  - 유지(목표±0.5kg): +150 / −250, 단백질 2.0g/kg
  - 증량(목표−0.5kg 미만): +300 / 0
- 유지 칼로리 = Mifflin-St Jeor × 1.55. 훈련일은 월~금, 플랜 시작 전과 토·일은 휴식일
- 추천 식단은 그날 목표에 맞춰 밥 양(0.5공기 단위)과 간식 탄수화물을 자동 조절
- 최근 30일 체중 그래프(78~79kg 유지 범위 띠), 7일 평균, 한 달 변화, 범위까지 예상 기간
- 추천 식단 4종(훈련일·휴식일 × 한식 집밥·호커 외식) — 식사 단위 또는 하루 전체 담기
- 아침 공복 체중 → 7일 평균이 왼쪽 체중 칸에 반영
- 저장 키 `bigthree500.nutrition.v1`, JSON 백업·복원

## 훈련 기능

- 주 5일 분할(월 하체 · 화 가슴 · 수 등 · 목 어깨·팔 · 금 하체 볼륨), 토·일은 헬스장 밖
- 메인 종목은 5/3/1: 월 스쿼트 · 화 벤치 · 수 데드리프트 · 목 OHP. 기준값(TM) = 1RM × 90%, 주차별 65·75·85 / 70·80·90 / 75·85·95 / 디로드, 마지막 세트는 AMRAP(+), 이어서 가벼운 반복(FSL) 5×5
- 사이클(4주)마다 TM 증량: 스쿼트·데드 +5kg, 벤치·OHP +2.5kg. 1RM 입력값이 바뀌면 그 사이클부터 다시 계산
- AMRAP 기록이 더 높은 1RM을 가리키면 자동 상향, 최소 횟수 미달이면 기준값 10% 하향을 안내
- 세션마다 근력 블록(5/3/1 + 가벼운 반복, 휴식 2~3분)과 근비대 블록(10~15회, 휴식 45~90초) 2단 구성
- 등·어깨·가슴은 각도를 나눈 보디빌딩식 구성 + 드롭세트·레스트포즈·슈퍼셋 태그
- 모바일 요약과 주간 세션 선택
- 종목별 실제 중량·횟수·RPE 기록, 완료 체크, 휴식 타이머
- 동작 순서·흔한 실수·쉬운 대체 동작 및 외부 참고 링크
- 선택한 본중량에 맞춘 웜업 무게·세트·반복·휴식 계산
- 실측 1RM과 추정 e1RM 구분, 측정일별 그래프, 다음 점검 일정과 연기
- 회복 주차는 모든 메인 운동 55% 2 × 5와 보조 2세트로 일관되게 표시
- 달력만으로 기준 1RM을 증가시키지 않고 실제 입력 기록 사용
- 주간 실행 화면에 5/3/1 파동과 `TM = 1RM × 90% + 사이클 증량` 계산식을 그대로 노출
- 동작 가이드에 사용 근육 다이어그램(주동근·협응근)과 이 프로그램에서의 역할 추가

기존 `bigthree500.v1`, `bigthree500.week.v1`, `bigthree500.tab` 저장 키를 유지합니다. 새 세트/측정 기록은 `bigthree500.training.v2`에 저장합니다. 기록은 브라우저·기기별이며 클라우드 동기화되지 않습니다. 운동 기록 영역에서 JSON 백업을 다운로드할 수 있습니다.

## 텔레그램 봇 (@daily3500bot)

사이트와 똑같은 5/3/1 계산으로 오늘 운동을 텔레그램에 보내주는 개인용 봇입니다. 사이트 자체는 그대로 정적 파일이고, 봇만 `api/`의 Vercel 서버리스 함수로 동작합니다.

- 운동하는 날(월~금) 아침 7시(싱가포르 시간)에 오늘 운동을 자동으로 보냄
- 처음 `/start`를 보낸 채팅이 주인. 다른 채팅에는 "개인용 봇이에요."만 답함
- 메인 종목은 세트별 무게·횟수, 마지막 세트는 "최대한", 나머지는 "N세트 × M회". 4주차는 가벼운 회복 주 안내
- 주말은 "오늘은 쉬는 날이에요." + 다음 운동 미리보기. 플랜 시작(10/19) 전에는 1주차 미리보기

| 명령 | 하는 일 |
| --- | --- |
| `/today` · 오늘 | 오늘 운동 |
| `/tomorrow` · 내일 | 내일 운동 |
| `/week` · 이번주 | 월~금 한눈에 (종목별 메인 세트 + 나머지 개수) |
| `/status` · 기록 | 지금 1RM, 합계와 500kg까지 남은 무게, 이번 주 기준값 |
| `/1rm 스쿼트 145` | 1RM 바꾸기 (스쿼트·벤치·데드·오버헤드). `/1rm 체중 78.5`로 체중도 |
| `/amrap 데드 107.5 6` | 마지막 세트 기록 — 추정 1RM이 더 높으면 자동 상향, 최소 횟수 미달이면 10% 낮추는 `/1rm` 명령을 알려줌, 회복 주는 기록만 |
| `/help` · 도움말 | 명령 목록 |

### 설정 (한 번만)

1. 텔레그램 @BotFather → `/mybots` → @daily3500bot → API Token 복사
2. Vercel → 3-500 → Settings → Environment Variables → `TELEGRAM_BOT_TOKEN`에 붙여넣기
3. Vercel → Storage → Upstash Redis(무료) 만들고 3-500 프로젝트에 연결 (`KV_REST_API_URL`·`KV_REST_API_TOKEN`이 자동으로 들어감)
4. Deployments → 가장 위 배포 → Redeploy
5. 브라우저로 https://3-500.vercel.app/api/setup 한 번 열기 (웹훅·명령어 등록. `ok: true`가 나오면 성공)
6. 텔레그램에서 @daily3500bot에 `/start`

사이트(브라우저)의 1RM과 봇의 1RM은 따로 저장됩니다. 사이트에서 1RM이 바뀌면 봇에도 `/1rm 스쿼트 145`처럼 알려주세요.

- 저장소를 연결하기 전에는 `/start`가 기본값(스쿼트 140 · 벤치 105 · 데드 135 · OHP 65 · 체중 78)으로 오늘 운동만 보여줍니다. 주인 잠금과 1RM·기록 저장은 안 됩니다 (`저장소(Upstash Redis)가 아직 연결 안 돼서 저장 못 했어요.`). `TELEGRAM_CHAT_ID`를 넣으면 저장소 없이도 주인만 쓰도록 잠글 수 있어요
- 선택 환경변수: `TELEGRAM_CHAT_ID`(주인 채팅 번호 고정), `CRON_SECRET`(설정하면 크론 호출에 `Authorization: Bearer` 필요, 없으면 `vercel-cron` User-Agent만 허용)
- 웹훅은 `sha256(TELEGRAM_BOT_TOKEN)` 앞 32자를 비밀 헤더로 검증합니다. 토큰은 코드·응답·로그에 남기지 않습니다
- 구조: `plan-data.js`(사이트·봇이 같이 쓰는 플랜 데이터) · `api/_lib/plan.js`(계산·메시지) · `api/_lib/store.js`(Upstash REST) · `api/_lib/bot.js`(명령 처리) · `api/telegram.js`·`cron.js`·`setup.js`(라우트) · `vercel.json`(크론 `0 23 * * 0-4` = 싱가포르 월~금 07:00)

## 검사

```sh
npm --prefix tests ci
npm --prefix tests test
```

계산 범위, 날짜와 점검 주기, 기존 저장값 유지, 세트 기록 복원 및 1RM 등록 흐름을 검증합니다. 봇 테스트(`tests/bot.test.cjs`)는 네트워크 없이 가짜 fetch로 웹훅 인증·주인 잠금·명령·크론·설정을 검증하고, 사이트(jsdom)가 만드는 세션과 봇이 계산한 무게·세트·횟수가 같은지도 비교합니다. 테스트 의존성은 `tests/`에만 두어 기존 정적 배포 방식을 유지합니다.

## 안내 기준

8주 점검 주기와 웜업 비율은 앱의 기본 템플릿입니다. 개인별 처방이나 의무적인 검사 간격이 아닙니다. 반복 기록으로 계산한 Epley e1RM은 실측과 다르며 여유를 남긴 세트에서는 과소 추정될 수 있습니다. 동작별 안내와 1RM 점검 화면에 HPRC·ACE·NASM 등 참고 링크를 제공합니다. 외부 시범 영상 링크는 검색 결과임을 명시합니다.
